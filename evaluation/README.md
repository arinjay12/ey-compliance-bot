# Evaluation Harness

A repeatable way to measure the compliance bot's quality: retrieval accuracy, answer
correctness, and a comparison against the same LLM used without retrieval.

## What's here

| File | Purpose |
|---|---|
| `gold_qa.json` | Gold-standard Q&A set. Every answer is grounded in the actual text of the source PDFs. Tagged by category, expected source document, and (for out-of-scope questions) marked unanswerable. |
| `eval_retrieval.py` | Measures **retrieval** quality: for each question, does a chunk from the *correct* document get retrieved? Fast (no LLM). |
| `eval_answers.py` | Measures **answer** quality and runs the head-to-head vs. a raw LLM. Slow (calls Llama 3 twice per question). |
| `calibrate_gate.py` | Measures nearest-chunk distances to calibrate the out-of-scope refusal threshold. |
| `results_*.json` | Machine-readable results from the last run. |
| `EVAL_REPORT.md` | Human-readable summary generated by `eval_answers.py`. |

## How to run

```bash
# from the project root
python evaluation/eval_retrieval.py     # retrieval hit-rate (fast)
python evaluation/eval_answers.py       # answer accuracy + vanilla-LLM comparison (slow)
python evaluation/calibrate_gate.py     # relevance-gate calibration
```

## How scoring works

**Retrieval** — A question is a *hit* if a chunk from its `expected_doc` appears in
the retrieved set. We report this for the shipped hybrid pipeline and for pure
semantic search, so we can see how much the keyword-injection step contributes.

**Answers** — Keyword-based grading against the gold set:
- An answerable question is **CORRECT** if every string in `must_all` appears AND
  each `any_of` group has at least one variant present (case-insensitive). Date and
  number variants are listed explicitly so phrasing differences don't cause false
  failures.
- An out-of-scope question is **SAFE** if the bot returns the refusal line, and
  **UNSAFE** if it answers anyway (a hallucination — the dangerous failure mode for
  a compliance tool).

Keyword grading is deliberately simple and transparent. It can occasionally
over-credit an answer that contains the right string for the wrong reason, so the
full answer text is always saved in `results_answers.json` for manual review.

## Why a head-to-head against a vanilla LLM?

The core question for any RAG system is *"does retrieval actually add value, or could
you just ask the LLM directly?"* `eval_answers.py` answers every gold question twice —
once through the full RAG pipeline, once with the same model and persona but **no
retrieved context** — so the accuracy gap is measured, not assumed.

## Extending the gold set

Add entries to `gold_qa.json`. Ground each answer in the source text (cite it in
`source_note`), pick a `category`, set `expected_doc`, and for unanswerable questions
set `answerable: false`. Keep a few genuinely out-of-scope questions — they are the
only way to test that the bot refuses instead of guessing.
